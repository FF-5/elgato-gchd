## Findings used for the driver (branch fix/analog-start-per-traces)

1. **Encoder for analog inputs:** every analog trace programs
   `v_format` 4 (NTSC) / 5 (PAL), `v_ip_format 0`, `v_in_source_type 3`,
   720×480/576, `v_h264_level 31`, `v_gop_size` 14 (NTSC) / 12 (PAL),
   also for 240p and 288p sources. `0x1004` bit 0 is never written (only
   `dma_sel_out = 1` at `0x1004`).
2. **Back end after lock** (composite and S-video, NTSC and PAL):
   `CA/E7/F1/CB/CA` reads; `98:04=95`; read `98:8B`; per-mode table
   (NTSC full `90–A3 = 01 BD … 81 49`; PAL sparse `90=D8 91=BF 95=9D
   96=1B 97=88 A0=8A A1=D8 A2=B2 A3=59`); read `98:89`;
   `72=88 C0=88 61=98 63=89 64=96 65=88`; read `98:FF`; `04=8D 62=91`;
   retrigger `0E=05/04`; retrigger `0E=15/14`; reads `FA/CA/E7/F1`.
   No calibration block A, no blocks B2/B3/C.
3. **Device state while idle on HDMI is `0x01`** (stopped, not IDLE); START is
   issued from `0x01` after `SCMD INIT A0`.
4. **START** completes in two rounds (`2008 = 01`, then `02`), both with
   `0074 = 011E`; first bulk completion about 0.1 s after the second round.
5. **288p PAL:** `0x88:CA` reads `7E` (same as 480i); `66` is NTSC 240p only.
6. **Decoder apply block** `0x88:07/08/09/28` appears only when lock is
   acquired after the input was selected without a source (noinput traces),
   twice: first `28=88`, then `28=8A` followed by `0A=98` (NTSC 240p) or
   `0A=8F` (PAL 288p). Not present when the source is already locked at
   selection.

## Upload 3 (2026-11-17): `composite/gchd_240p-480i_composite`, `hdmi/gchd_output_switch_hdmi`

Both recordings contain control and interrupt transfers only (no bulk data).
Bulk pipes appear only as USBPcap IRP_INFO records: `URB_FUNCTION_ABORT_PIPE`
(0x0002) on `0x81` and then `0x84`, once per restart, right after the STOP
completion is acknowledged (composite 20.055/54.250 s; HDMI 8.946, 19.493,
28.989, 40.141, 47.891, 60.439 s). No CLEAR_FEATURE / reset-pipe requests.

### Composite 240p <-> 480i (`gchd_240p-480i_composite`)

Both directions: decoder apply block (`28 = 88` to 480i, `8A` to 240p), ~0.4 s,
read `E7`, neutral back-end table (`70=C8 90=88 91..A3=77`, `6B`, `C0=80`,
`A2=77`, `58`, `C0=77`, common block), retrigger 05, NULL (~0.7 s), STOP
(~0.3 s), abort pipes, back-end table, retriggers 05+15 (480i) / 15+15 (240p),
120 encoder writes (identical both directions), INIT A0, START. Lock status
`CA`: `76` first after a change to 480i; `6E` first after leaving 480i (one
retrigger 15, then `66`). See `docs/composite.md §4` on `dev`.

### HDMI output size changes (`gchd_output_switch_hdmi`)

The HDMI source stays 1080p60 throughout (`v_format = 32`, `v_ip_format = 2`,
receiver timing reads unchanged); only the encoder output size changes. Each
change: NULL, STOP, abort pipes, (regular receiver poll), 120 encoder writes,
INIT A0, START. No receiver or back-end writes. NULL took 0.78, 0.72, 0.72,
1.43, 0.67, 0.80 s.
