# elgato_gchd — experimental V4L2/DKMS driver

Kernel driver for the Elgato Game Capture HD (`0fd9:0044/004e/0051/005d`).
It started as a port of the C++ userspace driver in [`../src`](../src) (a
read-only starting point) and adds what the C++ never had: input switching
while running, and work toward resolution changes. The protocol reference is
our own Windows USB traces, documented in [`../docs`](../docs). This README covers only building, layout
and the driver's current state.

> **Status: not working end to end.** This code is the tip of the
> `state-machine` branch (copied 2026-11-16). It builds cleanly against Linux
> 6.8 headers. On hardware (HD-New `005d`) it initializes, detects composite,
> and either fails to complete START or delivers H.264 that decodes badly. See
> "Known defects" and [`../TODO.md`](../TODO.md).

## Build and install

Firmware files must be in `/lib/firmware/gchd/` under the names the module
requests (no `.bin` suffix):

```
gchd/MB86H57_H58_IDLE        gchd/MB86H57_H58_ENC_H          (Original HD)
gchd/MB86M01_ASSP_NSEC_IDLE  gchd/MB86M01_ASSP_NSEC_ENC_H    (HD-New)
```

Use `../firmware_extract/` to get them from the Windows or macOS package.

Direct build:

```sh
make -C /lib/modules/$(uname -r)/build M=$PWD modules
sudo insmod elgato_gchd.ko
```

DKMS:

```sh
sudo dkms add ./dkms
sudo dkms install elgato-gchd/0.2.0
```

## Module parameters

| Parameter | Default | Meaning |
|---|---|---|
| `trace_mailbox` | `N` | Log every mailbox TX/RX byte (very noisy, useful for comparing with `docs/evidence/userspace-usbmon/`). |
| `ring_bytes` | 64 MiB | Byte cap of the PES ring. |
| `signal_active_retries`, `signal_inactive_retries`, `signal_poll_delay_ms` | see `input.c` | Signal-detection polling. |

## Source layout

| File | Contents |
|---|---|
| `gchd_protocol.h` | Every protocol constant: USB requests, banks, registers, enable bits, SCMD commands/states, mailbox ports and device addresses, bridge commands, device registers with a documented role, TS PIDs. Names follow `docs/commands.md`. |
| `gchd_mailbox.h` | The only way sequences talk to the device: `GCHD_FE_W/_R/_RX` (front end `0x9c`), `GCHD_DEC_*` (decoder `0x88`), `GCHD_BE_*` (back end `0x98`), `GCHD_AUX_W` (`0x94`), `GCHD_BRIDGE_W/_R/_SKIP`, `GCHD_TC_SET` (transcoder field), `GCHD_SEQ_*` table entries. **All of these return from the caller on error.** |
| `gchd_transcoder_fields.h` | Generated by `tools/gen-transcoder-fields.py` from `src/gchd_hardware.hpp`: `GCHD_TC_<FIELD>` = `address, lsb, bits`. |
| `elgato_gchd.h` | Driver structures, driver configuration (URB counts, buffer sizes), prototypes. |
| `usb.c` | USB control transfers, mailbox transport, SCMD and state completion, enable bits, firmware load, `gchd_hw_init()` / `gchd_hw_shutdown()`. |
| `input.c` | Encoder start, input-specific configuration and signal detection (HDMI, component, composite, S-video), mode changes. |
| `protocol_common.c` | Shared back-end blocks (`gchd_common_block_a/b1/b2/b3/c`). |
| `transcoder.c` | Encoder defaults, per-mode setup, final configuration. |
| `core.c` | V4L2 device and vb2 queue, lifecycle and workers, bulk-IN receive and TS parsing, USB probe/disconnect. |
| `fops.c` | `v4l2_file_operations`. |

Protocol code reads like the documentation:

```c
GCHD_FE_W(d, GCHD_FE_REG_INPUT_SEL, GCHD_FE_SEL_HDMI);   /* 0x9C:51 = 45 */
GCHD_DEC_R(d, GCHD_DEC_REG_LOCK, v);                     /* read 0x88:CA */
GCHD_TC_SET(d, GCHD_TC_V_HSIZE_OUT, 720);
```

Device registers without a documented role stay as hex literals; the macro
already names the device. Do not add aliases such as `REG_5B 0x5b`
(`RULES.md` D9).

### Planned layout (T-002)

`core.c` (1 900 lines) and `input.c` (1 500 lines) mix unrelated concerns.
Proposed split, one move per commit, each checked with
`tools/compare-objs.sh` / `tools/compare-mailbox-ops.py`:

| New file | Taken from |
|---|---|
| `transport.c` | control/register/mailbox/interrupt/firmware helpers from `usb.c` |
| `scmd.c` | SCMD, state completion, stream stop, enable bits from `usb.c` |
| `hwinit.c` | `gchd_hw_init/shutdown` (`usb.c`), encoder start and post-encoder blocks (`input.c`) |
| `input_common.c` | `protocol_common.c` plus setup subblock, colour space, `gchd_mail_seq` |
| `input_hdmi.c`, `input_component.c`, `input_analog.c` | the per-input configure/detect functions |
| `input.c` | dispatcher: configure/start/stop/detection, mode-change handling |
| `rx.c` | bulk-IN URBs and TS handling (rewritten in T-020) |
| `v4l2.c` | ioctls, vb2, controls, file operations (absorbs `fops.c`) |
| `core.c` | probe/disconnect, lifecycle, workers |

## Verification tools

| Tool | Proves |
|---|---|
| `tools/compare-objs.sh [--relaxed] [--alias old=new] OLD NEW` | Same machine code and string data (strict), or same calls and constants per function (relaxed). |

## Known defects (details and ordering in `../TODO.md`)

1. **240p is programmed as 480p** (`v_format 8`, `v_ip_format 2`) with a full
   reconfiguration on 480i ↔ 240p. Windows keeps the encoder in 480i and only
   flips analog decoder registers on 480i → 240p.
2. **Lossy H.264 delivery.** `gchd_ring_push()` drops the oldest PES when full,
   and `gchd_deliver()` delivers at most one PES per USB completion, so pictures
   are dropped. Audio and PTS/DTS are discarded. Plan: pass the TS through as
   `V4L2_PIX_FMT_MPEG` ([`../docs/video-output.md`](../docs/video-output.md)).
3. **START completion handling** does not follow the traced completion loop
   (`docs/hardware.md` §4.3: the loop ends on the target state). At commit
   `2da03ea` the device reached state `0x02` and streamed, while the driver
   reported START failed.
4. `transcoder.c` writes `0x1004` bit 0 under the comment "stout_mode".
   C++ `stout_mode` is bit 15. Marked `FIXME`; verify against a Windows trace.
5. `fops.c` exports a global symbol named `vb2_fops` with
   `EXPORT_SYMBOL_GPL`. This can clash with other modules and should be
   `static`.
6. The bulk-IN `0x84` endpoint is required at runtime (`-ENODEV` if missing).
   Windows queues it, but the C++ streamed without it.
7. Two errors in the analog path are ignored on purpose (the "anti-lockup"
   block in `input.c`, raw `gchd_mail_write()` calls without a check). This
   is kept from the port; review it when composite 480i is tested.
